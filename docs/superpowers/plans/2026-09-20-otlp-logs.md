# Optional OTLP log ingestion implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Accept explicitly annotated OTLP logs through an optional receiver that stores the same deterministic journeys as native SDK events.

**Architecture:** Add bounded JSON/protobuf codecs, a pure attribute-to-event mapper, and one encapsulated Fastify route that reuses existing authentication and ingestEvent. Default operation is unchanged; no Collector, exporter or additional service becomes mandatory.

**Tech Stack:** Existing Node.js 24/TypeScript/Fastify/PostgreSQL, explicit protobufjs 7.6.6 dependency already in the lockfile, official pinned OTLP schema descriptors, Vitest and an isolated official-exporter interoperability test.

**Spec:** `docs/superpowers/specs/2026-09-20-otlp-logs-design.md`.

## Global Constraints

- Execute after completed Python and Go native SDK work. No push, GitLab CI, publication, deployment, release-tag or account changes.
- `OTLP_LOGS_ENABLED` defaults to false; `/v1/logs` does not exist when disabled. Native SDKs always work without it.
- Support only OTLP HTTP logs on the existing listener. Traces, metrics, profiles and gRPC remain outside this receiver.
- Require stable caller event and journey IDs. Never generate event IDs, timestamps, runtime SDK identity or business failure outcomes in the adapter.
- Existing environment API keys authenticate requests; ingestEvent remains authoritative for scope, redaction, capture policy, hashing, aliases, diffs, idempotency and persistence.
- Accept JSON and binary protobuf, identity and gzip. Bound compressed/decompressed bodies; `OTLP_MAX_REQUEST_BYTES` defaults to 4,194,304 and accepts 1..67,108,864.
- Accept at most MAX_BATCH_EVENTS (100) records, checked before the first store. Empty export succeeds. No hand-written protobuf wire decoder or complete OTel SDK in the API.
- JSON uses OTLP hex trace/span IDs, integer enums and lowerCamelCase field names. Unknown message fields are ignored; mapped duplicate attribute keys and ambiguous AnyValue unions are refused.
- Successful/permanent partial exports return 200 with the matching response encoding. Transient storage errors return 503 without partialSuccess, even after earlier records committed.
- Safe fixed error codes/summaries only; no decoder/database messages, recorded values or keys in diagnostics or responses.

### Task 1: Bounded OTLP codecs and exact scalar handling

**Files:**
- Create `apps/api/src/otlp/{types,codec,codec.test}.ts` and `schema/` source/descriptor/generation/attribution files.
- Modify `apps/api/package.json` and pnpm-lock.yaml for explicit protobufjs 7.6.6; install only through the existing package manager.

**Interfaces:**
- `OtlpEncoding = "json" | "protobuf"`.
- `decodeExport(body: Buffer, encoding: OtlpEncoding): DecodedExport` returns typed resource/scope/record data with original order and `recordCount`. Preserve attribute arrays (including duplicates) and AnyValue presence for Task 2; preserve 64-bit integers exactly and bytes as bytes. Unknown fields do not become attributes.
- `encodeExportResponse({ rejectedLogRecords?, errorMessage? }, encoding): Buffer` and `encodeStatus({ code, message }, encoding): Buffer` produce only bounded protocol responses.
- `OtlpDecodeError` exposes a fixed safe code, never an underlying parser message.
- The task report gives exact exported canonical types and all resource/depth/count ceilings for Task 2.

- [ ] **Step 1: Add independent literal codec tests and observe RED.** Include an empty request, a minimal log, JSON/binary equivalents, uint64 maximum timestamp, negative int64 payload, nonzero mixed-case hex trace IDs, unknown fields, enum strings, malformed scalar types, truncated binary messages, unknown binary groups and nested AnyValue. Use independent precomputed bytes or an official generated encoder for expected binary input; encoding then decoding with the same new codec alone is insufficient.

```ts
expect(decodeExport(Buffer.alloc(0), "protobuf").recordCount).toBe(0);
expect(decodeExport(Buffer.from('{"resourceLogs":[]}'), "json").recordCount).toBe(0);
expect(() => decodeExport(Buffer.from([0x0a, 0x80]), "protobuf"))
  .toThrow(OtlpDecodeError);
// The raw JSON number must retain its exact source digits, not Number rounding.
const json = Buffer.from('{"resourceLogs":[{"scopeLogs":[{"logRecords":[{"timeUnixNano":18446744073709551615}]}]}]}');
expect(timestampOfFirst(decodeExport(json, "json"))).toBe(18446744073709551615n);
```

`timestampOfFirst` is a test helper reading the actual canonical timestamp field; no production mapper is used to generate an expectation.

- [ ] **Step 2: Generate the descriptor and implement strict decoding.** Use protobufjs schema parsing/Root APIs, not a bespoke binary decoder. Preserve library Long values until exact field conversion. The installed 7.6.6 Reader and generated decoders have recursionLimit=100, including skipType for unknown groups; keep bounds local or immutable, not mutable globals per request. Add explicit structural-count and AnyValue depth budgets and prove excess resource/scope/attribute/record structures fail before storage. Ensure binary decode cannot allocate an unbounded number of empty messages merely because they fit in the byte cap; a reader/message budget around the library may be used without reimplementing wire parsing.

For JSON, preserve numeric lexemes before any conversion to Number. Node24's JSON.parse reviver `context.source` was locally verified to retain `18446744073709551615` even though the ordinary parsed number rounds; use that capability or another exact supported parser. Accept both numeric and string representations permitted by ProtoJSON, including valid exponent forms, validate integer range/integrality without rounding, and bound exponent work. Validate known field types before protobufjs fromObject can coerce them. Honor ProtoJSON null-as-unset semantics, OTLP lowerCamelCase keys, integer enums, and hex IDs. Unknown fields are skipped rather than repackaged. A profiling-only common-schema string index has no log semantic value and is treated as empty/absent as the pinned schema specifies.

- [ ] **Step 3: Implement response codecs and test safe bounds.** Full success omits partialSuccess. Permanent partial response carries exact rejected count and a fixed bounded message; JSON int64 serialization follows ProtoJSON. Status errors contain only fixed numeric codes and fixed messages, with no arbitrary details. Check byte content independently for JSON/protobuf success, partial and error responses. Bound generated responses to a small constant because neither per-event values nor unrestricted error text are included.

- [ ] **Step 4: Run focused validation and commit.** Run codec tests, API typecheck, changed-file lint/format and descriptor reproducibility check. Verify the imported runtime descriptor survives the API build/image file-pruning rules while development schema sources do not become unnecessary runtime files. Report generated schema hashes/source commits and actual commands. Commit `feat(api): decode bounded OTLP log exports`.

### Task 2: Deterministic log-to-journey mapping

**Files:**
- Create `apps/api/src/otlp/{any-value,any-value.test,mapping,mapping.test}.ts`.
- Update canonical codec types only where the mapper reveals a necessary integration gap; retain Task 1 regressions.

**Interfaces:**
- Consume Task 1 DecodedExport and its exact scalar/presence representations.
- `mapExport(decoded: DecodedExport): readonly MappedLog[]` preserves record order. Each MappedLog is either `{ ok: true, envelope }` or `{ ok: false, code }`, with a bounded code. Envelope is protocolVersion 0.1 plus existing event fields, independent of database row types.
- Codec/byte/type failures remain whole-request errors; successfully decoded records with missing/invalid mapped business fields produce individual permanent refusals.

- [ ] **Step 1: Write mapping examples and observe RED.** Use the full attribute table in the spec as the binding map. Required identity/operation/name plus resource service/environment must retain their types. Test timestamp fallback, neither timestamp, overflow, integer nanosecond-to-millisecond truncation, uppercase IDs normalized to lowercase, all-zero/invalid IDs, explicit null/empty AnyValue, large integer payloads, bytes, arbitrary `__proto__` keys, duplicate mapped resource/log/map keys, ambiguous unions, metadata scalar constraints and explicit attempt precedence.

```ts
expect(mapOne(logWith({ timeUnixNano: 1700000000123456789n })))
  .toMatchObject({ ok: true, envelope: { protocolVersion: "0.1", event: { timestamp: "2023-11-14T22:13:20.123Z" } } });
expect(mapOne(logWithoutTimestamps())).toMatchObject({ ok: false });
expect(mapOne(sameLog)).toEqual(mapOne(sameLog));
```

Test helpers construct canonical decoded records, with literal required fields and resource attributes. They do not call the mapper to obtain expectations.

- [ ] **Step 2: Implement pure bounded conversion.** Decode AnyValue recursively within the agreed budget, preserving empty/null values, exact large-integer decimal strings, base64 binary values and safe data keys. Ignore body, severity, unmapped attributes and runtime guesses. Resource version becomes deployment.version. Never generate defaults for stable identity/time. Build optional fields only when explicitly mapped. Validate envelopes through the public protocol schema for precise existing limits; do not duplicate redaction/hash/storage behavior. A map-level semantic problem rejects that record, not unrelated records; resource required-field failure rejects each affected record.

- [ ] **Step 3: Verify equivalence and commit.** Feed independently equivalent JSON/protobuf records through codec then mapper and compare literal envelopes, including retries with omitted/zero timeUnixNano fallback. Test no cross-record mutation/shared map contamination. Run mapper/codec tests, typecheck and changed-file lint/format. Publish the exact MappedLog interface and safe code vocabulary in the report. Commit `feat(api): map annotated OTLP logs to journey events`.

### Task 3: Optional HTTP receiver and official-exporter integration

**Files:**
- Create `apps/api/src/routes/{otlp,otlp.test,otlp.integration.test}.ts`.
- Modify `apps/api/src/{app,server,auth-throttle}.ts`, config schema/load tests and necessary route metric labels.
- Create `examples/otlp-logs/` with a runnable annotated-export example and pinned test-tool requirements.
- Modify `.env.example`, relevant source/published Compose and Helm settings/tests, `docs/{DECISIONS,API_SPEC,OPERATIONS}.md` and a focused OTLP attribute/usage reference.

**Interfaces:**
- `registerOtlpRoutes(app, { keyring, maxEventPayloadBytes, allowFullPayload, maxRequestBytes })` registers an encapsulated plugin only when enabled.
- BuildAppOptions gains `otlpLogsEnabled?: boolean` and `otlpMaxRequestBytes?: number`; server passes validated config values. The later admission feature will pass its shared controller into this route.
- Reuse resolveApiKey/databaseApiKeys and normal key-touch behavior; extract a focused shared helper if necessary rather than duplicating its throttling policy.

- [ ] **Step 1: Add route tests and observe RED.** Disabled path is absent. Both encodings authenticate the environment key, refuse admin credentials and protect project/environment boundaries. Register scoped buffer parsers for JSON/protobuf and a scoped error handler. Cover identity/gzip, compressed and expanded over-limit bodies, malformed/truncated gzip, unsupported encodings/content types, a 101-record export, empty exports and unknown fields. All bad encoding/count requests must store zero records. Native JSON routes remain unchanged.

- [ ] **Step 2: Implement bounded request handling and storage responses.** Limit compressed input through Fastify bodyLimit and expanded output through zlib's bounded decompression or a counted stream, before codec parsing. Walk mapped logs in original order. Valid envelopes go through ingestEvent; permanent mapping/ingestion refusals accumulate only a count and fixed summary. First transient storage failure returns 503 without partialSuccess and stops starting further records. Already stored events remain committed; do not attempt compensating deletion. Match response content type for all supported request encodings, including parser/auth errors. Update bounded event metrics and exclude this path from the separate failed-admin-auth throttle.

- [ ] **Step 3: Verify real persistence, retries and native isolation.** Use a fresh test database with existing seed/key helpers. Test accepted alias/transformation/failure events, server redaction, payload diff and correct project queries. Force a transient failure after one stored record, retry the identical export and prove one row per stable event ID. Mixed permanent invalid records produce 200 partial success with exact count; no transient event is mislabeled permanent. Exercise query timeout, conflicting IDs and full-payload policy. Run relevant native ingestion/auth/body-parser regression suites.

- [ ] **Step 4: Run an official exporter against the receiver.** In an owned temporary Python environment install a pinned official opentelemetry-exporter-otlp-proto-http release compatible with its SDK. Record exact versions. Send annotated logs with batch size at most 100, query the local API for journey/alias/diff, then remove only that environment and stop owned servers/containers. The exporter is test/example tooling and never an API runtime dependency. Store a reproducible local command; no public telemetry endpoint or service is involved.

- [ ] **Step 5: Finish documentation and validation.** Add an ADR for explicit annotation and retry semantics. Document required attributes, stable IDs/timestamps, ignored body/severity, exact size/count limits, optional enablement and exporter batch settings. Wire only the two optional settings through Compose/Helm. Run codec/mapping/route/integration/config/docs checks plus changed-file build/typecheck/lint/format and local deployment rendering. Report code implemented versus publication/deployment still deferred. Commit `feat(api): expose optional OTLP log ingestion`.

## Plan self-review

Task 1 owns encoding and numeric fidelity; Task 2 owns deterministic semantic mapping; Task 3 owns authentication, optional routing, database behavior and operator/exporter evidence. Codec and mapper have separate meaningful review gates. All stages retain literal independent expectations, and the real exporter verifies interoperability beyond self-generated wire data. Settings, parser behavior and retry choices remain scoped to the optional receiver.
