# Node SDK public API before the first release: plan

Design: [`../specs/2026-09-16-sdk-api-v0-design.md`](../specs/2026-09-16-sdk-api-v0-design.md).

Each task is test-first: change or add the tests to the new surface, watch them
fail for the right reason, implement, update every caller in the repository in
the same commit (the demo, the example, the API's SDK tests, the conformance
harness and cases, the benchmarks, the docs the change touches), run the gate
(`pnpm format:check && pnpm lint && pnpm typecheck && pnpm test`), review the
diff, commit. Nothing that carries the product name is renamed. No em dashes in
docs or the CHANGELOG. Commits end with the `Co-Authored-By` trailer.

## Task 1: the SDK conformance suite reports no skipped tests

Files: `packages/sdk-node/src/conformance.test.ts`.

1. Run `pnpm test` and note 72 skipped.
2. Register "puts none of the listed text" and "reports the expected
   diagnostics" only for cases carrying `absentFromDiagnostics` or
   `diagnostics`, and generate per-case suites only for applicable cases (the
   manifest test already reports any that are not).
3. `pnpm test` reports no skipped tests. The API's
   `sdk-conformance.integration.test.ts` registers one unconditional test per
   applicable case; confirm and leave it.

## Task 2: diagnostics carry a code, one interface per kind, counters in one unit

Files: `packages/sdk-node/src/diagnostics.ts`, `safely.ts`, `queue.ts`,
`transport.ts`, `recorder.ts`, `label.ts`, `secret-names.ts`, `journey-id.ts`,
`config.ts`, `index.ts`, `conformance-harness.ts`; every SDK test that reads a
diagnostic or a counter; `apps/demo/src/recorder.ts`; `docs/OPERATIONS.md` if
it names a kind.

1. Tests: every diagnostic has a `code` from its kind's list and a `detail`
   object; `breaker_opened` is reported and counted in `breakerOpened`;
   `payload_omitted` carries the limit as its code (`too_large`, `too_deep`,
   `too_wide`) and `projection_failed` with `detail.error`;
   `delivered_first` and `insecure_endpoint` carry their fields in `detail`;
   `rejected` carries `detail.serverError`, a whole-request refusal
   `request_refused` with `{ events, httpStatus }`; `dropped` carries
   `queue_full`, `after_shutdown` (with `name` and `operation`), `shutdown`,
   `retry_budget` and `no_verdict`; `keysDropped` counts reports, not keys;
   `recorded` counts every event built, and `sent + rejected + dropped ===
   recorded` after shutdown in the accounting scenarios (clean run, queue
   overflow, unreachable endpoint, per-event refusal, recorded after shutdown,
   no verdict); `recorder.counters()` exists and `recorder.diagnostics` does
   not.
2. Implement: per-kind interfaces and code unions in `diagnostics.ts`;
   `safely` reports `unexpected_error` with `detail.error`; each report site
   names its code; `journeyIdSecretProblem` and `entityProblem` return a code
   with the reason; `ConfigProblem` carries a code; `across` reports a
   non-journey element as `not_a_journey` without throwing; `countRecorded`
   in the enqueue path, including an event refused after shutdown.
3. Rename `diagnostics()` to `counters()` in the recorder and every caller.

## Task 3: the journey surface

Files: `packages/sdk-node/src/recorder.ts`, `trace.ts`, `index.ts`,
`conformance-harness.ts`; SDK tests; `apps/demo/src/worker.ts`;
`apps/api/src/routes/journey-environment.integration.test.ts`;
`packages/protocol/conformance/sdk/identify-displayable.json`;
`docs/INGESTION_CONTRACT.md` section 9.

1. Tests: `continueJourney({ context, entity, label })` behaves as `consume`
   did (the context's id and entity win, `entity` is the fallback, `label` is
   set before anything is recorded, missing or unreadable options still give a
   journey); `continueJourney({ journeyId, entity })` continues that journey; a
   journey id that is not a non-empty string is reported
   (`journey_id_invalid`) and replaced; `consume` is gone;
   `fail(name, error, { metadata })` records the metadata; `identify` and
   `startJourney` take `displayableAliases`; `record` masks and bounds
   `error.stack` as typed; a callback returning a non-native thenable returns
   a native promise and `isFailure` receives the resolved value; type-level
   tests (`expectTypeOf`) for the thenable overload, the input generic, and
   explicit `undefined` in every optional input under
   `exactOptionalPropertyTypes`.
2. Implement the named option types (`Entity`, `StartJourneyOptions`,
   `ContinueJourneyOptions`, `IdentifyOptions`, `FailOptions`,
   `FinishOptions`, `ShutdownOptions`, `ErrorInput`, `CaptureMode`), `?: T |
   undefined` on every optional input, the `PromiseLike` overloads returning
   `Promise<Awaited<T>>`, `WrapOptions<T, I>`, and stop exporting
   `TraceContext`.
3. Callers: the demo worker (`continueJourney`, `fail` options), the API's
   environment test, the harness (`fail` takes `args.options`), the
   `identify-displayable` case, and the contract's description of a `fail`
   call.

## Task 4: propagation helpers and configuration names

Files: `packages/sdk-node/src/propagation.ts`, `config.ts`, `recorder.ts`,
`index.ts`, `conformance-harness.ts`; SDK tests; `apps/demo/src/integration.ts`,
`apps/demo/src/worker.ts`; `apps/api/src/ingestion/limits-agreement.test.ts`;
`packages/protocol/conformance/sdk/oversize-payload.json`; `docs/SDK_SPEC.md`
and `tests/docs-truth.test.ts` (the event budget default); `docs/OPERATIONS.md`.

1. Tests: `injectSqsAttributes(attributes, context)` returns a copy of the
   given attributes with the context added, and leaves the argument alone;
   `extractSqsContext`, `injectPayload`, `extractPayload` behave as the old
   helpers did; `extractHttpContext` reads a fetch `Headers`, ignores numeric
   values, and still reads a plain record; `maxEventBytes` and `propagation`
   are read and validated as the old names were, and the old names are no
   longer read.
2. Implement the renames and the `HttpHeadersInput`, `SqsMessageAttributes`,
   `SqsMessageAttributeValue`, `ContextEnvelope` and `ExtractedPayload` types;
   `@defaultValue` on every `RecorderConfig` option; `@experimental` on the
   helpers, `PropagationLevel`, `propagation`, `across`, `JourneyGroup`,
   `captureInput`, `captureOutput`, `journeyIdFor`, `journeyIdSecret`,
   `label`, `maxConcurrentSends` and `Counters`.
3. Callers: the demo, the limits agreement test, the oversize case, the docs
   truth test and `SDK_SPEC.md`, `OPERATIONS.md`.

## Task 5: the published package

Files: `packages/sdk-node/package.json`, `scripts/bundle.mjs`,
`scripts/bundle-options.mjs`, `scripts/pack.mjs` and
`scripts/release-manifest.mjs` (new), `src/package.test.ts` (new);
`scripts/publish-sdk.sh`; `pnpm-lock.yaml`.

1. Tests: after a build, `dist` holds exactly `index.js` and `index.d.ts`;
   `index.d.ts` imports nothing relative; the manifest's `engines.node` is
   `>=22.12.0`; `exports` has `./package.json` in both the manifest and
   `publishConfig`; the release manifest the pack script writes has no
   `devDependencies`, no `scripts` and no `development` condition.
2. Implement: API Extractor (dev dependency) rolls the declarations tsc emits
   into a temporary directory into `dist/index.d.ts`, with
   `declarationMap` off (no API report, see the design); the bundle
   targets `node22`; `scripts/pack.mjs` builds, packs with pnpm, strips the
   manifest and repacks with npm; `publish-sdk.sh` publishes that tarball.
3. Verify by hand: the tarball's file list; `npm install` of it in an empty
   directory; ESM `import` and CJS `require`; `tsc` over a file using every
   public entry point with `strict` and `exactOptionalPropertyTypes`, under
   `node10`, `node16` and `bundler`, with a deep import of `dist/config`
   failing under each.
